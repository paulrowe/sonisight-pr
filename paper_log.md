# SoniSight — paper log

Running record of experiments, decisions, and results. Append, don't rewrite.
Every reported number should be traceable to an entry here.

---

## Locked decisions

- **Task framing.** Binary triage: `normal` vs `suspicious`, where
  `benign` and `malignant` both map to `suspicious`. Rationale: the tool's job is
  deciding who needs further workup, not rendering a diagnosis. This differs
  from most published BUSI evaluations (benign-vs-malignant or 3-class) and must
  be stated explicitly anywhere numbers are compared.
- **Split.** `busi_split.json`, 70% dev / 30% test, stratified by class, seed 42,
  generated by `make_split.py`. Committed and frozen.
- **Development discipline.** All tuning, debugging, threshold selection, and
  model fitting on dev only. Test scored once, after freeze.
- **No metric-chasing.** Changes are justified by a mechanism, validated on
  hand-checked images. Aggregate movement alone is not a justification.
- **Expert review is a separate track** from the ablation, so feedback cannot
  contaminate the quantitative results. Claim language: "solicited structured
  expert review of outputs and methodology." Never "clinically validated."

## v1 — hybrid pipeline (Gemini bbox → OpenCV descriptors → rules)

### Bugs found and fixed

1. **Gemini invented lesions on normal tissue.** The ROI prompt asked it to
   "find the single most prominent mass," presupposing one exists. Rewrote to
   judge *presence* first and return `None` for normal tissue, artifacts, and
   speckle.
2. **Segmentation rejected real tumors.** `segment_candidate()` filtered out
   contours that touched the image border, filled >45% of the frame, or had
   solidity <0.30. Those rules were written for whole-image search but were
   being applied to tight Gemini ROI crops — where a real mass legitimately
   touches all four edges, fills the frame, and (if spiculated) has low
   solidity. Made the filters ROI-aware.
3. **Saliency fallback manufactured false positives.** When Gemini correctly
   returned "no lesion," the code overrode it with a saliency guess that always
   finds something. Gated behind `USE_SALIENCY_FALLBACK`, default off.

### Dev results (546 images, threshold 0.30)

| stage | sensitivity | specificity |
|---|---|---|
| original | 0.450 | 0.925 |
| + ROI prompt fix | — | — |
| + ROI-aware segmentation | 0.885 | 0.570 |
| + fallback disabled | 0.843 | 0.839 |

Operating threshold 0.30 selected on dev: specificity is flat from 0.50 down to
0.30 while sensitivity rises, so 0.30 dominates 0.50.

### The finding that ended v1

| system | AUROC (dev) |
|---|---|
| full v1 rule-based pipeline | 0.830 |
| `mass_present` bit alone | 0.830 |
| trained model, all v1 descriptors (5-fold CV) | 0.834 |
| trained model, descriptors minus `mass_present` | 0.834 |

The OpenCV + rules stage contributed **no measurable discriminative signal**.
Prediction agreed with "did Gemini return a box?" on 536/546 images (98.2%).

Error decomposition: all 71 false negatives were images where Gemini returned no
box despite a lesion being present (45 benign, 26 malignant). All 15 false
positives were images where Gemini boxed normal tissue. **Zero errors originated
in the classifier.**

Cause: relaxing the segmentation gates (fix #2) made the descriptor extractor
degenerate — 348/372 boxed cases labeled "spiculated," 299/372 "irregular," mean
circularity 0.398 (suspicious) vs 0.395 (normal).

**Conclusion: the v1 "hybrid" was functionally a Gemini lesion detector. The
entire error budget is detection, not characterization.** This is a reportable
negative result about hybrid LLM+CV pipeline design.

## v2 — genuine hybrid (in progress)

Design requirement: each component must contribute signal the other cannot.

**Detection cascade** (targets the 71 false negatives)
1. Structured Gemini assessment (JSON: presence, bbox, shape, margins,
   echogenicity, orientation, posterior, suspicion), 3 samples, majority vote on
   presence, median bbox, mode on categoricals.
2. Recall-oriented sensitive second pass on negatives.
3. CV proposes high-recall candidate regions; Gemini verifies each crop.

**Characterization** (fixes the dead features)
- GrabCut seeded from the bbox, replacing Otsu on a tight crop
- Continuous features an LLM cannot measure by eye: `depth_width_ratio`,
  `posterior_shadow`, `margin_sharpness`, `angular_margin_var`, GLCM texture,
  `rel_echogenicity`
- 10% ROI padding; removed the 5% edge crop inside ROIs

**Scoring:** logistic-regression fusion head over Gemini + CV features, fit on
dev with 5-fold CV (`fit_fusion.py`), with a transparent rule score as fallback.

### Synthetic validation (before any real-data run)

| feature | benign-like | malignant-like |
|---|---|---|
| circularity | 0.851 | 0.277 |
| solidity | 0.992 | 0.715 |
| depth_width_ratio | 0.688 | 1.126 |
| angular_margin_var | 0.116 | 0.227 |
| posterior_shadow | −0.111 (enhancement) | +0.191 (shadowing) |

Candidate proposer localized a synthetic lesion at (240,194,121,93) against
ground truth (240,195,120,90).

**Status: not yet run on real BUSI images.** Synthetic separation is a
necessary, not sufficient, check — real ultrasound speckle is harsher and
GrabCut will fail on some images.

### Open question

`fit_fusion.py` reports AUROC for Gemini-only, CV-only, and fused feature groups
on dev. If fused does not beat both single-source heads by a meaningful margin,
the pipeline is not meaningfully hybrid and the paper reports that. In v1 the
gap was +0.000.
